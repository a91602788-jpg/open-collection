# Как выбрать проект / Choosing a project

[Catalog](../README.md) · [Start here](start-here.md)

1. **Задача / Scope.** Is this an application, a library, a starter or a learning example? Identify the part you still need to build.
2. **Условия / Terms.** Read the actual license file, package licenses, enterprise-module terms and trademarks. A GitHub SPDX detection is only a pointer. Public source, open source, a free tier and a free hosted service mean different things.
3. **Расходы / Costs.** Check infrastructure, storage, email, model APIs, payment fees and optional enterprise features. A free repository does not imply free operation.
4. **Размещение / Deployment.** Confirm supported self-hosted and hosted modes in official documentation. Do not infer them from the presence of a Dockerfile.
5. **Поддержка / Maintenance.** Review releases, maintainer responses, upgrade notes and security policy. Push timestamps may come from bots or documentation edits.
6. **Интеграция / Integration.** Check authentication, tenant isolation, data export, backups, accessibility and localization where your use case requires them.
7. **Проверка / Evaluation.** Try the project in an isolated environment with sample data. Verify the important user flows and a restore before relying on it.

Ни одна запись каталога не является гарантией безопасности или готовности к production. Если метаданные отсутствуют, это обозначено явно; отсутствие распознанной лицензии не означает разрешение на использование.

Catalog inclusion does not certify security or production readiness. Missing metadata is explicit; an unrecognized license is not permission to use a project.
